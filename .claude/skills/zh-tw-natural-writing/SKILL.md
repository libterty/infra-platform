# 台灣中文自然寫法：去 AI 味

讀的人要的是「看一遍就懂、知道要做什麼」。AI 寫的中文常常字都對，但讀起來要停下來想、或聽起來像在演講。這份 skill 的工作是把它改回像真人寫的，**內容一個都不能多、一個都不能少**。

## AI 中文為什麼聽起來怪

- **翻譯腔**：用英文的語序寫中文。名詞片語放句首當主詞、條件與原因放在後面、被動句、一長串「的」。
- **鋪陳代替陳述**：句子在宣告「這很重要」，而不是給出事實。「不是 A，而是 B」「值得注意的是」「歸根究柢」。
- **照規則打節奏**：什麼都三個一組、每段結尾一句金句、到處破折號。
- **膨脹**：普通的事寫成關鍵、全面、深度、賦能。
- **照規則排版**：每個項目都加粗、每段都有小標題。
- **殘留物**：聊天的客套話、改稿過程的痕跡、跟沒人提過的反對意見爭論。

## 工作流程

1. **先查事實，再改句子。** 改說法之前確認這句話是真的。每個數字、時間、門檻、規則都要指得到出處（程式碼、規格、實測、使用者給的資料）。指不到就不要寫，**絕對不要自己訂一個數字或規則讓句子更完整**。描述系統行為前先讀程式碼；換了範例，要連帶檢查引用那個範例的說明。
2. **標出毛病。** 整份讀一遍，標出下面每一類毛病，從最嚴重的開始。也看段落的形狀：每段都三點、每段都用同一種收尾，是同一個毛病放大。
3. **改寫。** 保留每一個有根據的主張。可以縮短、合併、拆段、改結構，但資訊要在。不要加任何來源沒有的事實、名稱、數字、日期。某句需要你沒有的細節，就問，或寫一句比較簡單的。
4. **自己念一遍。** 問：哪裡還像 AI？哪句要停下來想才懂？有沒有多加或漏掉事實？再專門找最常殘留的五種：「不是…而是」、結尾金句、破折號、三連排比、粗體標籤。
5. **定稿。** 把意思重新講一遍，不要一個詞一個詞地補丁。一句改不順，就以它的重點重寫整段。長短句交錯。

拿不準意思的句子，不要硬改，列出來問人。

### 語氣

使用者給了範例，就先讀範例，照它的句長、用詞、標點、開頭與轉折寫；範例優先於下面所有規則。

沒有範例時，看文體決定：
- **技術文件、手冊、規格、報告**：中性、平實，像資深同事當面講給你聽。口語但正式，不客套、不宣傳。
- **訊息（Slack、Email、回覆同事或客戶）**：更口語、更短，先講結論。
- **部落格、心得、個人文章**：保留作者的意見、猶豫、幽默與題外話。

去掉毛病只做了一半，結果還要像一個人寫的。

### 回傳什麼

- **貼上的文字（預設）**：回改好的版本，必要時附幾組「原句 → 新句」說明改了什麼。
- **檔案模式**：使用者指定檔案時，只改文字。程式碼區塊、行內程式碼、指令、路徑、欄位名、JSON／YAML、連結目標一律不動；章節標題與目錄不動（有些工具靠標題產生目錄頁碼）。改完給簡短摘要，一次改很多句時挑 5～10 組「原句 → 新句」給使用者看，不要只說「改好了」。
  - **規範用語與數字不能升降。** 「必須／須／不得／不可／應／不應該／可」、MUST／SHOULD／MAY、數字、門檻、上下限，原文寫什麼就照原字保留，不能改弱也不能改強，也不能把規定改寫成描述。例如「遇到沒見過的值不得當成錯誤」不能改成「不要因此出錯」；「`general` 也只能是全館共用」不能改成「一定是全館共用」，前者是限制，後者讀起來像在描述現況。
- **嵌在其他任務裡**（寫 PR、commit、文件時順便套用）：只回最終文字。

## A. 翻譯腔與中文語序（中文特有，最常見）

### 1. 抽象名詞片語當主詞

**留意：** 句首是「……的……」「……跟……」這類名詞片語，後面接評論。
**問題：** 英文習慣用名詞當主詞，中文習慣用「人或系統做什麼」當主詞，並且先講因再講果。
**改前：** 留白跟忘了填，在檔案裡看不出差別。
**改後：** 系統分不出是故意留白還是忘了填，所以上傳後請看結果檔，確認哪些欄位變成空的。

### 2. 條件、原因放在後面，或只用逗號硬接

**留意：** 「B，在 A 的時候」「B，因為 A」、兩個子句之間只有逗號。
**問題：** 中文是「如果 A，就 B」「因為 A，所以 B」。只用逗號，讀者要自己猜關係。
**改前：** 被拿掉了哪些，寫在結果檔的 `removed_items`。
**改後：** 哪些被拿掉寫在結果檔的 `removed_items`。
**改前：** 這種檔案沒有商品，不能用整批覆蓋。
**改後：** 這種檔案不更新商品，所以不能用整批覆蓋：整批覆蓋會刪掉檔案裡沒有的商品，用在這裡會整館清空。

### 3. 被動句與「被」字濫用

**留意：** 被……所……、被進行、被用來、由……來……
**問題：** 中文少用被動。「被」多用在不好的事（被罵、被刪掉）。能說誰做了什麼，就直接說。
**改前：** 該設定會被系統讀取並被用來決定是否進行核准。
**改後：** 系統讀這個設定，決定要不要自動核准。

### 4. 「進行」「對……進行」「作為」「基於」「透過」這類英文介系詞的直譯

**留意：** 進行……的動作、對 X 進行 Y、作為一個……、基於……、透過……的方式、針對……、關於……方面
**問題：** 多半是 perform / conduct / as / based on / via 的直譯，拿掉之後句子更短更清楚。
**改前：** 我們將對資料庫進行查詢的動作，基於查詢的結果來作為判斷依據。
**改後：** 先查資料庫，再看結果判斷。

### 5. 一長串「的」與代名詞「其」「它」

**留意：** 一句話三個以上「的」；「其」「它」「該」指代不清。
**問題：** 英文所有格與 it/its 的直譯。讀者要回頭找「它」是誰。
**改前：** 該工具的設定檔的路徑的格式需符合其規範。
**改後：** 設定檔的路徑要照工具規定的格式寫。

### 6. 從系統內部角度寫，讀者要自己推結果

**留意：** 只描述機制（「會跳過」「不受影響」「會被忽略」），沒講讀者會看到什麼。
**問題：** 讀者要的是結果。能舉例就舉例，例子比規則好懂。
**改前：** 群組裡可以有主商品自己，推薦時會跳過。
**改後：** 把 A、B、C 放進同一組，三個都掛這組：看 A 時推 B、C，看 B 時推 A、C，不會推到自己。

### 7. 只講規則、不講後果，讀者會照字面誤解

**留意：** 「照原樣留著」「保持不變」「不用管」這類讀者可能讀成相反意思的說法。
**改前：** 只想改一格，其他格照原樣留著。
**改後：** **留白會清空，不會保留舊值。** 所以只想改一格時，其他格也要照原本的內容填著，不能留白。

## B. 鋪陳代替陳述

### 8. 不是 A，而是 B

**留意：** 不是……而是……、不只是……更是……、與其說……不如說……、拆成兩句的版本（「這不代表 A。這代表 B。」）、句尾的否定小尾巴（「……，不用猜」）。
**問題：** 前半句否定一個沒人說過的東西，好讓後半句聽起來更大。直接講重點。只有前半句真的在糾正讀者的誤解時才保留。
**改前：** 這不只是一個工具，更是團隊協作的基石。
**改後：** 團隊用這個工具同步進度。

### 9. 結尾金句、單句段落

**留意：** 段落最後一句重述前面的話；「這才是真正的關鍵。」「值得我們深思。」每一節都用同樣的收尾。
**問題：** 要讀者停下來回味，卻沒有新資訊。刪掉重複的那句。

### 10. 鋪陳開場與假裝坦白

**留意：** 讓我們來看看、以下將為您介紹、接下來、首先我們需要了解、說實話、老實說、重點來了、這裡要特別注意
**問題：** 宣告要講重點，卻還沒講。直接講。

### 11. 跟不存在的反對意見爭論

**留意：** 這並不是說……、需要澄清的是、有人可能會認為……但、你可能會想……但
**問題：** 回答沒人提過的質疑，通常是改稿留下來的。刪掉；裡面有真的主張就直接講。

### 12. 聽起來很深的套話

**留意：** 歸根究柢、本質上、真正的問題是、核心在於、某某的底層邏輯、閉環、抓手
**問題：** 普通的點被包裝成深刻的道理，沒有多給任何細節。換成具體的主張。

## C. 照規則打節奏

### 13. 硬湊三個

**問題：** 意思只有兩點，也要湊成三個排比（「高效、穩定、可靠」）。每一項都要是不同的意思；不是就合併，或只留最有力的那個。真的有三件事時才寫三件。

### 14. 一句塞三件事

**留意：** 一句超過兩個逗號、混了規則、原因、建議。
**改前：** 整批覆蓋會刪掉檔案裡沒有的商品，填「否」等於上傳的當下就刪，沒有人能在寫入前再看一次，整批覆蓋一律建議填「是」。
**改後：** 整批覆蓋會刪掉檔案裡沒有的商品；如果填「否」，一上傳就會刪，沒有人能先檢查。所以整批覆蓋請填「是」。

### 15. 破折號到處用

**規則：** 定稿不用破折號（——）連接子句，除非使用者的範例本來就這樣寫。改成句號、逗號、冒號或括號，或重寫句子。程式碼、指令、路徑裡的不動。
**問題：** 破折號讓寫的人不必決定兩個子句的關係。
**範圍：** 文件所屬的寫作規範對破折號另有規定時（例如 `align-spec`、`report`、`runbook` 這幾支 skill 的範例本身就用破折號），以那份規範為準。

### 16. 疊加保留語

**留意：** 可能、或許、某種程度上、在一定程度上、理論上來說，一句疊兩三個。
**問題：** 每個主張都變得不確定。只有來源真的不確定時才保留一個。
**範圍：** 只刪說明文字裡多餘的保留語。規格條款、約束、欄位定義裡的「可能」「通常」「至多」是內容的一部分（例如「這個欄位可能整批都沒有」），一律不動。

## D. 用詞與膨脹

### 17. AI 高頻詞

**留意：** 賦能、助力、打造、深度、全面、無縫、至關重要、不可或缺、持續、致力於、值得一提的是、需要注意的是、此外、總而言之、綜上所述、在當今……的時代、扮演著重要的角色、帶來了顯著的提升
**問題：** 這些詞讓每句話聽起來都一樣。換成具體的動詞與事實，或直接刪掉。

### 18. 填充與強調詞

**留意：** 等於、也就是說、沒有例外、這一點、不受……影響、沿用……時、以確保、進行……的動作、相關的、一定程度
**改前：** 「試算」不受這一列影響：填什麼都一樣自動核准、不寫入資料庫。
**改後：** 試算不看這一列，一律自動跑完，不寫資料庫。

### 19. 誇大意義與宣傳腔

**留意：** 標誌著、里程碑、革命性、劃時代、極大地、顯著地、一站式、最佳實踐、業界領先
**問題：** 普通的事被寫成重大事件。照實寫發生了什麼。

## E. 排版與殘留

### 20. 粗體當裝飾、小標題過多

**問題：** 每個項目都加粗，粗體就沒有重點了。一段只粗一個真正的重點。兩三段的內容不需要小標題。

### 21. 聊天殘留

**留意：** 希望這對你有幫助、如有任何問題歡迎隨時詢問、當然可以、好的、以下是……的內容、作為一個 AI
**問題：** 這些是對話的包裝，不是文件的內容。刪掉。

### 22. 描述前一版，而不是現況

**問題：** 文件與註解寫「這個改成了……」「原本是……現在是……」。只有變更紀錄、release note、遷移指南才講前一版；其他文件只寫現在怎麼運作。

### 23. 內部語境外洩到對外文件

**留意：** 給客戶或外部讀者的文字裡出現內部環境名稱、帳號 ID、PR 編號、內部路徑、內部代號、同事名字。
**問題：** 讀者看不懂，也可能洩漏資訊。換成讀者看得懂的說法或佔位符（「實際值請向〇〇索取」）。

## F. 台灣用語與標點

- 用台灣慣用詞：資料（不是數據，指 data 時）、資料庫、軟體、網路、程式、設定（不是配置）、預設（不是默認）、支援（不是支持）、透過（不是通過，指 via 時）、品質（不是質量）、訊息（不是信息）、影片（不是視頻）、專案（不是項目，指 project 時）、檔案（不是文件，指 file 時）。
- 全形中文標點（，。：；「」），引號用「」與『』，不用 “”。
- 中文與英文、數字之間的空格依文件既有慣例；沒有慣例時加半形空格。
- 數字、欄位名、程式碼用原文，外面加反引號。

## 什麼時候不要改

- 每個毛病都是一種預設寫法，人也可能刻意這樣寫。單一個弱信號（一個「此外」、一個破折號）不用改，好幾個毛病集中在同一段才動手。
- 引文、標題、專有名詞、正在討論這個詞的句子，不改。
- 使用者已經親自定稿的句子，不改。
- 改了會讓意思變的，不改，先問。例如使用者想把專有說法換掉、換上的詞意思不同時，指出差別並提一個意思不變的替代說法。

保留帶有作者個性的細節：具體而少見的細節、真實的猶豫與矛盾、有年代感的說法、作者說得出理由的第一人稱選擇、真心的題外話。

## 改完自查

1. 念一遍，像不像台灣人當面講話？有沒有哪句要停下來想才懂？
2. 每個數字、門檻、規則都追得到出處嗎？有沒有自己加的？
3. 有沒有漏掉原文的任何事實？
4. 最常殘留的五種還在不在：「不是…而是」、結尾金句、破折號、三連排比、粗體標籤。
5. 檔案模式：用腳本比對改前改後，程式碼區塊、行內程式碼、標題行、表格欄數都沒變。
6. 對外文件：掃一次內部名稱（環境名、帳號 ID、內部路徑）。
